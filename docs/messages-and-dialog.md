# Messages and dialog

Facts from `disasm/out/gamelow.s` / `game.s`, from decoding all 438 room
blocks (`tools/room.py`, `tools/messages.py`) and from the `$D000` font in
`build/dumps/ingame.bin`.  `assets/messages.json` and
`assets/message-xref.json` are generated by `tools/messages.py`.

Related: docs/room-format.md (the creature descriptor `$E0`-`$F1`),
docs/menus-and-saves.md (the `$3C00` jump table, save block, visions),
docs/assets.md (the `$D000` message font).

## Text encoding

All in-game text is **ASCII**, written byte-for-byte into screen RAM.  It
is not PETSCII and not C64 screen codes: the font at `$D000` (2 KB of RAM
under the I/O area, seen by the VIC because bank 3 has no character-ROM
shadow) is ASCII-ordered, so `$41` draws `A`, `$20` a blank, `$27` an
apostrophe.  The raster split at `$8AAF` points `$D018` at `$D000` for
rows 20-24 only; rows 0-19 use the room charset at `$C800`.

Bit 7 is the reverse-video flag, never part of a character: `$A0`-`$FF` in
the font are the reverse complement of `$20`-`$7F`.  Both string printers
OR `$80` into every character when the flag `$A8` is non-zero, which is
how menu items and the selected inventory line are highlighted.

There are no control codes in any string.  Line breaks are positional
(see "Screen layout" below).

## The message table -- `$4500`

187 strings at `$4500`-`$55C7`, each terminated by `$FF`, laid end to end
with no index.  `assets/messages.json` has all of them with addresses.

`print_message` (`$3C15`, jump-table entry `$3C00`) takes the 1-based
message number in A and the screen address in X (low) / Y (high):

```
$80/$81 <- X/Y      destination
$82/$83 <- $4500    cursor
$84     <- A
loop: dec $84; when it hits 0, copy from ($82) to ($80) until a byte
      with bit 7 set; otherwise skip forward past the next $FF and repeat
```

So message 1 is the string at `$4500`, and skipping is linear -- printing
message 187 walks the whole 4.3 KB table.  The terminator test is `bmi`,
i.e. any byte with bit 7 set ends a string; only `$FF` is ever used.
Nothing bounds-checks the number, but no descriptor holds one above 187.

Four call sites, all in the dialog verbs:

| site | screen | row, col | prints |
|------|--------|----------|--------|
| `$3CCE` | `$C349` | 21, 1 | SPEAK line 1 (`$09E7` or `$09EB`) |
| `$3CD8` | `$C371` | 22, 1 | SPEAK line 2 (`$09E8` or `$09EC`) |
| `$410F` | `$C352` | 21, 10 | the emotion (`$09E9` or `$09ED`), after the label `EMOTION:` |
| `$4162` | `$C3C1` | 24, 1 | the pensed message (`$09EA` or `$09EE`) |

No code anywhere loads a literal message number; every number comes out
of the room block.  The table is therefore reachable only through the
creature descriptor.

| both speech and pense | 84, 137 | 2 |

The first 34 entries are one contiguous block of emotion words, ending in
the unused `NOTHING`; the five later emotions (`FEAR`, `PITY`, `WARMTH`,
`SADNESS`, `EXCITEMENT`) were evidently appended after the block was
frozen.  135 and 171 are single `*` placeholders that keep the numbering
of the strings around them.

Nothing is random: **PENSE EMOTIONS does not pick an emotion**, it prints
the one number the room block names, `$09E9` if the standing gate passes
and `$09ED` if it fails.  Same for every other slot.

## Screen layout

The playfield is rows 0-19 (`$C000`-`$C31F`).  Rows 20-24
(`$C320`-`$C3E7`) are the text and status area; `$C3F8`-`$C3FF` are the
sprite pointers.  `clear_textline` (`$940E`, reached through `$9506`)
zeroes `$C320`-`$C3F7` -- all five rows.

Both printers write **contiguously** from the given address with no
wrapping logic, so a string longer than the rest of the row simply runs
into the next row.  Every message line starts in column 1, so a logical
line is 40 characters of which the first 39 occupy columns 1-39 and the
40th lands in column 0 of the following row.  Every multi-line inline
string in the binary is padded so that characters 39, 79 and 119 are
spaces -- verified for all 14 of them.

Addresses used as line starts:

| address | row, col | used for |
|---------|----------|----------|
| `$C349` | 21, 1 | first message line |
| `$C352` | 21, 10 | emotion word (after `EMOTION:`) |
| `$C357` | 21, 15 | `NO RESPONSE` for SPEAK / EMOTION (`$439A`) |
| `$C371` | 22, 1 | second message line |
| `$C399` | 23, 1 | the `MESSAGE:` label |
| `$C3A2` | 23, 10 | `NO RESPONSE` for MESSAGE (`$43AE`) |
| `$C3C1` | 24, 1 | the pensed message |

Message lines in the table are at most 39 characters (the longest, 107
`THE HERMIT: EARN D'OL NESHOM'S BLESSING` and 156 `PENSE THE ANIMALS IF
YOU HAVE THE POWER`, fill columns 1-39 exactly), so nothing in the table
wraps.

Every message ends by falling into `$AC12` -> `$A7B2`: wait for input,
then any joystick move or fire clears the text area and returns to play.

## `print_inline` -- `$8009` -> `$828B`

All fixed text is inline after the `JSR`.  The routine pulls the return
address, reads a 2-byte destination, copies bytes until one has bit 7 set
(that byte is not stored), then `jmp ($00A2)` through the recomputed
continuation address.  `$A5` is the output index, so writing is
sequential from the destination.  It does not clear `$A8`.

136 call sites; `tools/messages.py --inline` lists them.  One of the 136
(`$94F7`) is inside a dead copy of the `$94ED` fragment and is not code.

## The response gate -- `npc_gate` `$43C2`

```
ldx $0A8F        ; low nibble of the block's $E1
lda $0A68,x      ; $0A68 standing with Kindar, $0A69 standing with Erdlings
cmp $0A8E        ; high nibble of $E1
rts              ; carry set = pass
```

`$9940` splits `$09E1` when the creature is spawned: `and #$0F` ->
`$0A8F` (which standing to test), four `lsr` -> `$0A8E` (the level
required).  Carry set (standing >= level) selects the `$E7`-`$EA` set,
carry clear the `$EB`-`$EE` set.

Only two stat indices occur on disk, so the gate is always "your standing
with one of the two peoples":

| `$E1` | stat | level | rooms |
|-------|------|-------|-------|
| `$00` | Kindar | 0 | 76 |
| `$01` | Erdling | 0 | 33 |
| `$11` | Erdling | 1 | 1 |
| `$20` | Kindar | 2 | 1 |
| `$30` | Kindar | 3 | 5 |
| `$31` | Erdling | 3 | 3 |
| `$40` | Kindar | 4 | 2 |

Levels 0 and 1 always pass (no character starts either standing below 0,
and only Herd starts a standing at 0).  The starting standings are in the
per-character table in docs/menus-and-saves.md.

## Adjacency -- `npc_adjacent` `$4364`

Returns carry set when all three hold:

- the creature's column `$0A80` is `$0A10 + $0A37` or `$0A10 + 2*$0A37`
  (one or two cells in the direction the player faces, `$0A37` = +/-1);
- the creature's row `$0A81` is within 1 of the player's row `$0A18`;
- the player's facing `$0A37` differs from the creature's facing `$0A85`
  -- they must be looking at each other.

This matches the manual: "Move close to another game character.  Be sure
you are facing each other."

## SPEAK -- `verb_speak` `$3C48`

1. clear the text area (`$9506`).
2. `$09E0` = 0 (no creature in the room) or `npc_adjacent` fails ->
   `SPEAK WITH WHOM?` (`$3C53`), done.
3. If the gate passes **and** `$09F1` = 0 (the plain gift-giver kind):
   - `find_gift_item` (`$3D4E`), see below -- it can abort the whole verb;
   - if `$2380 + $09F0` low 7 bits equals today (`$0A62`), print
     `COME BACK TOMORROW, MY FRIEND` (`$3C8B`) and stop.  That is the
     once-a-day limit on gift NPCs.
4. Re-test the gate and pick the pair (`$09E7`,`$09E8`) or
   (`$09EB`,`$09EC`).  If the first is 0 -> `NO RESPONSE` at `$C357`.
   Otherwise print it at `$C349`, and the second at `$C371` if non-zero.
5. Stamp the day: `$2380 + $09F0` <- (old & `$80`) | `$0A62`.  This
   happens for every creature, not just gift-givers.
6. If the gate passes, set `$CC` = 1 ("something was offered") for
   `$09F1` in {`$00`, `$40`, `$20`-`$2F`, `$D0`}; `$D0` additionally sets
   `$CE` = 1.
7. If `$09F1` = `$40` and bit 7 of `$2380 + $09F0` is still clear: set
   that bit, `$0A67` += 5, `$0A63` = `$0A67`, play a random tune, and run
   `gain_spirit_power` (`$3DA9`).  One spirit level per such NPC per
   quest.

The five `$40` creatures are the blessers: rooms 19 (`THE WISE CHILD: THE
BLESSED ONE LIVES`), 41 (`THE HERMIT: EARN D'OL NESHOM'S BLESSING`), 116
(Raamo's mother), 191 (`D'OL NESHOM: MY BLESSING QUESTER` /
`I GRANT YOU THE SPIRIT BELL`) and 492 (Vatar).  Five times 5, plus 1 for
each of the ten animals below, is 35 on top of the starting limit -- more
than enough for the whole skill ladder.

## PENSE -- `verb_pense` `$407B`

1. clear the text area.
2. `$09E0` = 0 -> `PENSE WHOM?` (`$4086`).  Note there is **no**
   adjacency test here: emotions work at any range within the room, as
   the manual says.
3. `$0A67` (spirit limit) < 5 -> `YOU LACK THE SPRIT SKILL` (`$40A1`,
   with the typo).
4. `$0A63` (spirit energy) = 0 -> `YOU NEED MORE SPIRIT ENERGY`
   (`$40C7`).
5. Print `EMOTION:` at `$C349`, then message `$09E9` (gate passes) or
   `$09ED` (fails) at `$C352`; 0 -> `NO RESPONSE` at `$C357`.
   `dec $0A63`.
6. The MESSAGE half runs only if all of:
   - `$0A67` >= 10 (the PENSE MESSAGES skill);
   - `$0A63` still non-zero after the emotion;
   - `npc_adjacent` now passes -- messages need speaking distance;
   - not (`$09F1` = 1 and bit 7 of `$2380 + $09F0` already set), i.e. the
     animal has not already been pensed.
7. Print `MESSAGE:` at `$C399`, then `$09EA` / `$09EE` at `$C3C1`; 0 ->
   `NO RESPONSE` at `$C3A2`.  `dec $0A63` again, so a full pense costs 2.
8. If `$09F1` = 1: set bit 7 of `$2380 + $09F0`, `inc $0A67`, `$0A63` =
   `$0A67`, play a random tune, `inc $DD`; when `$DD` reaches 5 run
   `gain_spirit_power`.

Ten creatures have `$09F1` = 1 -- rooms 67, 98, 126, 134, 158, 192, 213,
296, 316 and 496, all species 6 or 7 (the animals).  Every one of them
carries the same pair: emotion 152 `WARMTH`, message 151 `THE SPIRIT
RISES WITHIN`.  Pensing each once raises the spirit limit by 1, and the
`$DD` = 5 test means only the fifth prints the congratulation.  Hence
message 156, `PENSE THE ANIMALS IF YOU HAVE THE POWER`.

`gain_spirit_power`, the skill names and the vision sequence are in
docs/menus-and-saves.md.

## Gifts -- `$09EF` and `find_gift_item` `$3D4E`

`$EF` is an **object class**, the same 0-14 index `tile_range_lookup`
(`$A790`) produces from an object table index and `$AFD4` turns into a
name at `$AFF7`:

| class | name | class | name |
|-------|------|-------|------|
| 0 | A SPIRIT BELL | 8 | A TOKEN |
| 1 | A SPIRIT LAMP | 9 | A TRENCHER BEAK |
| 2 | A HONEYLAMP | 10 | WISSENBERRIES |
| 3 | A WAND OF BEFAL | 11 | A VINE ROPE |
| 4 | A ROAST LAPAN | 12 | THE TEMPLE KEY |
| 5 | PAN BREAD | 13 | D'OL FALLA'S KEY |
| 6 | FRUIT & NUTS | 14 | A STRANGE ELIXER |
| 7 | A SHUBA | | |

`$10` is the one out-of-range value and means **a nid**, i.e. the NPC is
offering a place to rest rather than an object.  (Twelve creatures use
it; docs/room-format.md previously read `$10` as "gives nothing", which
is backwards.)

`find_gift_item` returns at once when `$09EF` = `$10`.  Otherwise it
scans object indices `$FE` down to 0 for the first object that is in this
room (`$0D00,x` = `$86` and bit 7 of `$0F00,x` agrees with `$87`), is on
the ground (`$0F00,x` & `$40`) and is not held (`$0F00,x` & `$20` clear).
If it finds none it pops its caller's return address and prints
`I HAVE NOTHING MORE TO GIVE` (`$3D62`), ending SPEAK before any line is
said.  The index it does find is discarded -- the routine exists only for
that abort and for the `$10` shortcut.

What actually transfers the object is TAKE (`$AD52`): with `$CC` set it
requires the class of the object under the player to equal `$09EF`
(`$AD91`), otherwise `IT WAS NOT OFFERED TO YOU` (`$AD99`).  `$CC` is
cleared once the take succeeds.  REST (`$AC15`) is the mirror for the nid
case: away from home it needs `$CC` set and `$09EF` = `$10`, else
`NO ONE OFFERED YOU A NID` (`$AC53`).

`$EF` is only ever consulted for creatures whose `$F1` can set `$CC`
(`$00`, `$40`, `$20`-`$2F`, `$D0`) or that are merchants (`$80`); the
other 84 creatures leave it 0.

## OFFER -- `verb_offer` `$43CC`

Cycles the carried inventory on row 21 (`$C356`) and dispatches on the
creature's state index `$09F0` -- not on the room:

| `$09F0` | creature | accepts | result |
|---------|----------|---------|--------|
| `$49` | Raamo, room 464 | class 7 (shuba) or 11 (vine rope) | `$9C18` -> `$9E17`, the endgame |
| `$34` | guard, room 352 | class 10 (wissenberries) | `inc $D0`; on the second one `$2334` <- `$80`, permanently unlocking the `$C0` gate |
| `$35` | guard, room 32 | class 8 (a token) | `YOU MAY ENTER` |

Anything else -> `THAT WON'T HELP` (`$4487`); any other creature ->
`NO RESPONSE`.  Both guard paths fall through `$44C3`, which sets `$CD` =
1 and removes the offered object.  `$CD` is cleared by `load_room`
(`$8BB9`), so it only opens the door for this visit; `$2334` is in the
saved block and is permanent.  `$96B9` reads them: `$F1` = `$C0` opens on
`$2334` or `$CD`, `$F1` = `$C1` on `$2335` or `$CD`, else
`THE DOOR IS LOCKED` (`$96D1`).  Nothing ever writes `$2335`, so the
`$C1` gate in room 32 has to be paid for on every visit.

## BUY and SELL

Both start with `$4338`: `$09F1` must be `$80`, else
`THERE IS NO MERCHANT HERE` (`$4342`) and the verb aborts by popping its
caller.  Then `npc_adjacent`, else `NO RESPONSE`.

BUY (`$4194`) needs a token in the carried slots `$0F6C`-`$0FB6`, else
`YOU NEED MORE TOKENS`; needs `$0A7A` + 4 < `$0A6C`, else
`SORRY, YOU'RE CARRYING TOO MUCH`; then spends the token, sets `$CC` = 1
and says `TAKE WHICHEVER ONE PLEASES YOU` -- so BUY only grants
permission, and TAKE's `cpy $09EF` test is what limits you to the stock.

SELL (`$4234`) offers the inventory; classes with a 1 in the table at
`$4329` (2, 4, 5, 6, 7, 9, 10, 11) are sellable.  A free carried slot is
required, else `SORRY, I'M NOT INTERESTED`; otherwise the object becomes
a token (`$60` written into `$0F6C,x`) and `HERE'S YOUR TOKEN`.

The eight merchants and their stock (`$EF`): room 26 roast lapan, 37
fruit & nuts, 38 trencher beak, 39 honeylamp, 46 wissenberries, 64 shuba,
68 vine rope, 69 pan bread.  Each says its pitch as `$E7` and `ONLY A
TOKEN` (127) as `$E8`.
